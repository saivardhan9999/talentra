Class follows docket rule group 6 as currently tagged in the model; the reviewed classes are in [step 12](12-data-classification-register.md).

**Columns on every business table** (not repeated): `created_at` timestamptz NOT NULL (when the row was created), `created_by` bigint FK → app_user (who created it; NULL = a system process), `updated_at` timestamptz NOT NULL, `updated_by` bigint FK → app_user (NULL = system); all set by the `set_audit_columns` trigger, so no caller can fake them.

## How to read and join

- Every table has a surrogate `id`. A column `<table>_id` references that table; a role-named key says its role first (`sourced_by_app_user_id`, `blocked_organisation_id`).
- Columns ending in a lookup name (`application_status_id`) reference an enumeration; join its `code` for logic and `ui_text(ui_label_id, <language>)` for display.
- Times are `timestamptz` in UTC; show them in `app_user.time_zone`. Money is always beside its `*_currency_id`.
- Row-level security filters every business table by the signed-in user, so a query returns only what that user may see.

**Worked example**, written only from this dictionary: applicants of job 2044 by stage, labels in Hindi.

```sql
SELECT p.full_name, ui_text(s.ui_label_id, 2::smallint) AS stage, a.applied_at
FROM application a
JOIN candidate_profile p ON p.id = a.candidate_profile_id
JOIN application_status s ON s.id = a.application_status_id
WHERE a.job_requirement_id = 2044
ORDER BY s.sort_order, a.applied_at;
```
